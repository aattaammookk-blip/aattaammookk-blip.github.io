# 人相食主题总库

二十四史（含《清史稿》）中「人相食」相关记载的搜集、整理与考辨。

**双击 `index.html` 即可使用。** 不联网、不安装、不需服务器。

---

## 这是什么

本库是《正史中的人相食》（下称一库，201 事件）与《正史中的人相食·二库》（下称二库，补遗层）**合并后的主题总库**。一库、二库的原始文件均未改动；总库另立目录，数据、地点表、原文包独立成一套。

一套以事件为锚点的专题数据库，把正史里散落的「人相食」记载整理成可检索、可比较、可溯源的结构化材料，严格区分两类性质不同的东西：

| 类别 | 数量 | 说明 |
|---|---|---|
| 正式事件 | **260** | 判定为实际发生的人相食事件，构成名录、时间轴、地图的主体 |
| 关联史料 | **397** | 260 条事件所辖的记载条数（含二库挂靠 22 条） |
| 排除材料 | **323** | 检索命中而不符合收录标准：同形异义、修辞、典故、占辞讹言、泛述、族俗、割股疗亲 |

两类合计 **720 条记载**，即全库「人相食」相关记载的总数。事件数不等于史料数，也不等于检索命中数。

> **合并口径**：一库 201 事件／311 记载／210 排除；二库 61 事件／66 记载／21 挂靠／113 排除。合并时剔除 1 条重复立目（EV2017 与一库 EV0044 同篇同句）、降级 1 条（EV2049 与一库 EV0110 同事异书，改作挂靠），其余全部并入。逐条理由见 `docs/03_二库并入说明.md`。

## 功能

- **事件名录**：固定双栏。左侧列表（年代、朝代、地点、类型、概述、史料数、判定），右侧详情（基本信息／概述／全部史料原文），各自滚动，切换事件不跳动。
- **史料原文**：按底本偏移还原为**完整自然段**（繁体，未删节），命中句黄底高亮，缺字红框标出；可一键显示机器转换的简体对照。
- **整篇原文**：每条史料可点「查看整篇原文」，弹出该篇全文（**479 篇**，繁体，未删节），自动滚到命中处并标黄。原文按史书拆成 25 个文件，点开才加载，不影响首屏。
- **时间轴**：朝代分区＋年代刻度＋类型着色节点，支持 1×–8× 缩放；区间事件画长条、推定年份画空心虚线圆点。只保留筛选下拉，不设搜索框。
- **就地预览**：在地图、时间轴、地点索引、人物索引里点事件，先在当前页弹出预览窗（与名录详情同源，含完整史料），再由窗内「跳转至事件名录」按钮跳转，不再一点就跳页。
- **历史地图**：三段式（控制区／地图主体／右侧详情）。地形晕渲 + 海岸线 + 湖泊 + 分级水系，墨卡托投影，水陆边界与矢量同源（无错缝）；缩放 1×–6×、平移有边界；点位按 12 px 聚合，可切换「事件点位／密度分布」，按朝代、年份、类型、定位精度筛选；点地点看事件、点事件进详情。**不画国界与历史疆域**。
- **地点索引**：246 处地点按区域分组（含今地与定位精度）。一条事件并列数地者在索引与地图上按单地拆开，可从任一子地点查到该事件（事件自身地点字段仍照录原文）。
- **人物索引**：236 位人物按关联事件数排列，可搜索，点开看其事件表；一条记载并列数人者按单名拆开。两个索引各自独立成页。
- **搜索与筛选**：关键词覆盖编号、年代、朝代、地点、人物、类型、史书、篇名、原文、概述；**输入后按回车或点「搜索」才开始检索**，不会边打字边跳转。支持朝代／类型／地点／年份区间／精度／**史书**组合筛选与四种排序。
- **排除材料**：独立入口，按 13 族 21 类归并；新增「割股类」「毁尸·刑罚」「未遂未食」「人胆入药」四类。

## 运行方式

直接双击 `index.html`。全部资源以相对路径的普通 `<script src>` / `<link>` 引入，不使用 fetch、ES module、CDN 或任何在线服务，因此 `file://` 协议下功能完整（整篇原文的动态载入亦已在 `file://` 下验证）。

**关于体积**：`index.html` 只有 8 KB，是页面骨架；数据在 `assets/data.js`（1.76 MB），整篇原文在 `assets/texts/`（14.5 MB）。首屏只加载约 1.86 MB，整篇原文点开才载入对应那一部（最大 1.9 MB）。若不需要整篇原文，删掉 `assets/texts/` 即可，史料卡中的命中段落不受影响（按钮会提示原文未随包提供）。

若浏览器对本地文件有限制，用任意静态服务器打开亦可：

```bash
python -m http.server 8000
# 浏览器访问 http://127.0.0.1:8000/
```

浏览器要求：Chrome / Edge / Safari / Firefox 近三年版本。不支持 IE。

## 数据来源与限制

- 史文取自电子转录的二十四史全文库（25 部、3725 篇、约 3207 万字），经关键词检索、机器预判、人工复核后抽取要素。一库、二库同出一源。
- **底本不是校勘定本**，未与纸本逐字校对，不得标注为「中华书局点校本某卷某页」。正式引用须核对纸本或权威影印本。
- 繁简混排（多数繁体，少数篇目简体），未统一转换；部分篇目含私用区缺字，页面以红色 □ 标出。
- 二库的判定口径与一库略有出入（割股单列一类、挂靠不另立事件等），总库保留其判定，只统一类目名、史书写法与句位；二库原归「原因不明」的石邃食尼、朱有熺掠食生人两条，总库并入「习俗仪式型」。详见 `docs/03_二库并入说明.md`。
- 详细口径、字段定义、判定标准、已知问题，见 `docs/` 与页面内「资料说明」。

## 重建数据

```bash
cd 人相食主题总库
python build/build_merge.py    # 读一库 data.js、二库 data.json、素材库原文 → 总库 data.js / places.js
python build/build_texts.py    # 读总库 data.js 引用的篇目 → assets/texts/
```

两个脚本**只读**一库与二库，不改动原始文件。`build_merge.py` 同时生成 `build/merge_report.json`，记录剔除、降级、挂靠、句位校正、改判与新增地点，可逐条复查。

> 并列数地事件的逐地点拆分写在同一脚本的 `SPLIT` 表中（一库 38 条沿用原 `place_split.json`，二库 7 条为合并时新增）。重建地点表后须同步重建 `place_index`，否则地图与地名索引会退回「一条事件只落一点」。

# 一、数据结构说明

本文件说明【人相食主题总库】的数据结构。总库由一库（原库，201 事件）与二库（补遗层，61 事件）合并而成，数据结构与一库保持一致，仅在一处新增字段（`records[].linked_event`）。

## 1. 文件构成

```
人相食主题总库/
├── index.html              入口（页面骨架，不含数据）
├── assets/
│   ├── app.css             样式
│   ├── app.js              交互逻辑
│   ├── data.js             数据层 window.DB（1.76 MB）
│   ├── places.js           window.PLACE_GEO / EVENT_PLACE / EVENT_PLACES
│   ├── basemap.js          矢量底图（海岸线／湖泊／水系）
│   ├── terrain.jpg         地形晕渲
│   ├── about.js            资料说明正文
│   └── texts/              479 篇整篇原文，按史书分 25 个文件（14.5 MB，按需加载）
├── docs/                   六份说明
└── build/                  合并与导出脚本、合并报告
```

## 2. `window.DB` 顶层

| 键 | 类型 | 说明 |
|---|---|---|
| `meta` | object | 标题、口径、计数与分布 |
| `bands` | array | 时间轴朝代色带（16 段） |
| `scale_pts` | array | 时间轴刻度锚点 |
| `type_colors` | object | 五种事件类型的配色 |
| `events` | array | 正式事件 260 条 |
| `nonevents` | array | 空数组（一库复核后该类目已取消，保留键位） |
| `excluded` | array | 排除材料 323 条 |
| `place_index` | array | 地点索引 246 条 |
| `person_index` | array | 人物索引 236 条 |
| `place_audit` | array | 一库的 40 条地点复核记录，原样保留 |

### `meta`

```js
meta = {
  title, subtitle, source, updated, built,
  counts: { events, nonevents, excluded, records, records_events,
            records_nonevents, records_all, places, persons, books },
  dynasty, type, prec, century, book, excl_type,   // 分布，均为 {名称: 条数}
  dynasty_order, type_order                        // 排序依据
}
```

`counts` 以事件所辖记载为准：`records = records_events = records_all = 397`，`nonevents = records_nonevents = 0`。

## 3. `events[]`

字段与一库完全一致，顺序亦同：

`id, kind, year, year_text, prec, dynasty, place, type, n_records, n_indep, main_src, overview, note, audit, rank, century, same_source, reclass, records`

| 字段 | 说明 |
|---|---|
| `id` | 事件编号。一库 EV0001–EV0201；二库补遗 EV2001–EV2061（其中 EV2017、EV2049 未并入，见 03） |
| `kind` | 固定 `"event"` |
| `year` | 公元年，公元前为负数；无纪年者为 `null` |
| `year_text` | 年代原文，如「景福二年（893）」 |
| `prec` | `exact` 单年／`range` 区间／`approx` 推定 |
| `dynasty` | 朝代，取值见 `meta.dynasty_order` |
| `place` | 事件地点，照录整理后的地名串（并列数地者保留顿号原样） |
| `type` | 灾荒型／战争型／报复刑罚型／习俗仪式型（「原因不明」为预留类别，当前无事件） |
| `n_records` | 所辖记载条数＝`records.length` |
| `n_indep` | 独立记载数（同句去重后）；一库原值保留，二库事件取建库值，宿主事件按新增记载累加 |
| `main_src` | 主要出处，按记载顺序去重，以「、」连接 |
| `overview` | 白话提要（非史料） |
| `note` / `audit` / `rank` / `reclass` | 判定记录；总库中一库原值保留，二库事件留空 |
| `century` | 世纪，由 `year` 推得（如 893→「9世纪」，−594→「前6世纪」） |
| `same_source` | 同源组标记；二库事件为空数组 |
| `records` | 所辖记载数组 |

## 4. `records[]`

`seq, book, pian, pian_class, person, year, year_prec, year_text, place, event_place, type, verdict, quote, hit_preview, place_fix, note, audit, explain, reason, excl_type, rank, reclass, file_path, sent_start, sent_end, full, full_sim, hs, he, pua`

其中新增一个可选字段：

| 字段 | 说明 |
|---|---|
| `linked_event` | 仅挂靠记载有。值为宿主事件编号，标明该条系二库补入，非事件原有记载 |

其余关键字段：

- `book`：史书名，统一为简体（旧唐书、新唐书、旧五代史……）。
- `pian`：篇名，照录底本篇题；二库篇名多带卷次，未作删削。
- `quote`：页面引文（可能含省略号），用于检索与「命中原文」。
- `hit_preview`：命中句。
- `full`：**底本自然段**，未删节；由 `sent_start/sent_end` 经 `para_bounds` 取出，段落超过 1200 字时退化为前后各一句。
- `hs` / `he`：命中句在 `full` 中的起止偏移；`full[hs:he]` 与底本 `[sent_start:sent_end]` 逐字相同（已全量校验）。
- `full_sim`：`full` 的 OpenCC t2s 机器转换，仅供阅读。
- `pua`：`full` 中私用区缺字数。
- `file_path`：底本篇目路径，形如 `texts/舊五代史/武皇紀下.txt`，与 `assets/texts/` 的键一致。

## 5. `excluded[]`

字段与 `records[]` 基本相同，另加：

| 字段 | 说明 |
|---|---|
| `seq` | 序号，字符串，1–323 连续 |
| `_eid` | 内部编号 EX0001–EX0323 |
| `excl_type` | 排除类别，21 类（见 02） |
| `explain` | 排除理由 |
| `reason` | 判定记录（规则编码） |
| `reclass` | 复核改判说明 |

排除材料的 `type` 与 `excl_type` 取同值，`verdict` 固定「非事件之记载条目」。

## 6. `place_index[]`

`name, level, region, count, events, variants`

- `name`：定位表使用的基名（去括注；「京师（长安）」归入「长安」）。
- `level`：州县／区域／通语／部族。
- `region`：河洛、关中、齐鲁、河北、河东、江淮、荆楚、江南、巴蜀、陇右、塞北、岭南、跨区域、部族、通语、其他。
- `count`：关联事件数（一地多属、一事件多地者各计一次）。
- `events`：事件编号数组。
- `variants`：同一地点的其他写法（事件 `place` 原文）。

索引名称与 `places.js` 中实际使用的名称严格一一对应，故筛选下拉不会出现「选了却查不到」的空项。

## 7. `person_index[]`

`name, count, records, events`

- `count`：关联事件数；`records`：相关记载条数。
- 只统计正式事件；「不详」「无（志体不系人）」「无（城守）」等占位值不入索引。
- 一条记载并列数人者（「董璋、姚洪」）按单名拆开计。

## 8. `places.js`

```js
window.PLACE_GEO   = { 地名: [今地, 经度, 纬度, 精度, 说明] }
window.EVENT_PLACE = { 事件号: [ {n,m,x,y,p,note} ] }      // 一事件一点（或首个点）
window.EVENT_PLACES= { 事件号: [ {n,m,x,y,p,note}, ... ] } // 并列数地者逐地拆分
```

定位精度：`exact` 精确地点／`county` 州县级／`region` 区域级／`macro` 大范围／`unknown` 不详／`doubt` 存疑。`macro` 与 `unknown` 的 `x`、`y` 为 `null`，不落点。

`EVENT_PLACES` 只对并列数地的事件存在（一库 38 条、二库 7 条），其余事件读 `EVENT_PLACE`。

## 9. `texts/`

```js
window.TEXT_FILES = { "史記": "b01", ... }        // 史书（目录名）→ 文件编号
window.TEXTS["texts/史記/楚世家.txt"] = "……"      // 篇目路径 → 全文
```

共 25 部、479 篇。点「查看整篇原文」时才注入对应那一部（最大 1.9 MB），首屏不加载。

## 10. 与一库的结构差异

1. 新增 `records[].linked_event`（仅 22 条挂靠记载）。
2. `meta.title` 改为「人相食主题总库」，`counts` 与各分布按合并后重算。
3. 事件编号不连续：EV0001–EV0201 之后接 EV2001–EV2061，缺 EV2017、EV2049（理由见 03）。
4. 排除材料新增「割股类」「毁尸·刑罚」「未遂未食」「人胆入药」四类，序号续编 211–323。
5. 其余字段名、字段序、取值域均未改动。

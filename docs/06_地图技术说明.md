# 六、地图模块技术说明

## 一、这一版改了什么

上一版地图只有 9 条河、一层经纬网和 133 个点，底图是空白的纸色，看不出地形，也没有海岸线；「定位精度」筛选里还留着「精确地点」「不详」两个没有任何点位的选项。这一版按「一张完整的专题地图」重做：

| 项 | 旧版 | 现版 |
|---|---|---|
| 底图 | 空白纸色 + 9 条河 | 地形晕渲（Natural Earth 1:50m）+ 海岸线 + 湖泊 + 分级水系 |
| 投影 | 等距圆柱 + 纬度余弦校正 | Web 墨卡托，栅格与矢量严格对齐 |
| 视野 | 固定，与画布比例不符时留白边 | 按画布比例自适应，始终铺满 |
| 水系 | 32 段 | 435 段（按 `scalerank` 分两级粗细） |
| 海岸线 | 无 | 409 段 / 11497 点 |
| 湖泊 | 无 | 229 个面 |
| 点位 | 直接画，重叠时无法点击 | 屏幕空间 12 px 聚合，重叠自动合并 |
| 布局 | 筛选条 + 地图 + 侧栏 | 控制区 / 地图主体 / 右侧详情 三段式 |
| 精度筛选 | 6 个选项，其中 2 个恒为 0 | 只列实际存在的等级并带数量 |

## 二、三层数据，互不改写

用户要求「自然地理底图、事件数据、历史地名必须是三个独立的数据层」。当前实现严格照此分层：

| 层 | 载体 | 内容 | 是否可被视觉操作改动 |
|---|---|---|---|
| ① 自然地理底图 | `assets/terrain.jpg` + `assets/basemap.js` | 地形晕渲、海岸线、湖泊、水系、经纬网 | 否。图层开关只控制显隐，不改数据 |
| ② 事件数据 | `assets/data.js` + `assets/places.js` | 事件、史料、地点定位 | 否。地图只读，不写回 |
| ③ 历史地名 | `assets/places.js` 的 `n` 字段 | 史料原文地名（去括注基名） | 否。地名注记只是渲染，不回写 `events[].place` |

三层的连接点是 `EVENT_PLACE[event_id] → {n, m, x, y, p, note}`：地名给注记，坐标给点位，精度给样式。并列数地的事件另存 `EVENT_PLACES[event_id] → [{n,m,x,y,p}]`，一个事件可在图上落多点；两张表都只读，不回写 `events[].place`。任何一层的改动都不影响另外两层。

## 三、底图构建

`build/build_basemap.py` 在构建阶段完成全部重活，运行时只读结果。

### 1. 地形晕渲

- 源：Natural Earth **1:50m Natural Earth I with Shaded Relief and Water**（公有领域），全球 10800×5400，0.0333°/px。
- 裁切：东经 68–143°、北纬 12–55°。`tfw` 给的是左上**像元中心**（-179.9833, 89.9833），裁切按**像元边界**（-180, 90）换算，避免半个像元的系统偏移。
- 横向缩放到 2400 px，**纵向重采样到墨卡托**：逐行按 `y = ln(tan(45°+φ/2))` 反算纬度，取源图对应行（四舍五入到最近像元），保证栅格与矢量在同一投影下逐像素对齐。
- **水体按矢量掩膜重绘**（见下节）。
- 调色：饱和度 ×0.88、亮度 ×1.03、对比 ×1.02，再与暖白 (250,244,233) 混合 10%，贴近全站宣纸底。
- 输出 `assets/terrain.jpg`，2400×1729，**1.2 MB**（quality 92、4:4:4 无色度抽样）。

### 1b. 水陆边界与矢量同源

1:50m 栅格自带的海岸线比 1:10m 矢量粗得多，两者叠加时会出现肉眼可见的错缝——尤其在群岛、河口、三角洲。仅靠调投影无法消除，因为差异来自数据本身的精度。

现做法：用 `ne_10m_land` 多边形在 3× 超采样画布上栅格化为水陆掩膜（初始全水，陆地填 0，内陆水域再填 255），缩小到目标尺寸得到 0–1 的边缘覆盖率 α，据此把地形图的水体部分重绘为统一海洋色：

```
sea = (160,191,206) + clip((亮度 − 水域平均亮度) × 0.78, ±34)
out = 原地形 × (1 − α) + sea × α
```

- 边界由 1:10m 多边形决定，与叠加的矢量海岸线同源，误差降到 1 px 量级（2400 px 宽图上实测平均 2.9 px，其中含 JPEG 边缘与线宽本身的影响）。
- 海底的明暗起伏保留 78%，不至于压成一块平色。
- 小岛、沙洲在 1:50m 栅格上本就被简化掉，掩膜按 1:10m 补回，因此不会出现「矢量画了岛、地形却没有」的错位。

### 2. 矢量

| 层 | 源 | 处理 | 结果 |
|---|---|---|---|
| 海岸线 | `ne_10m_coastline` | 裁切 → 墨卡托 → RDP 抽稀（ε=0.012°） | 409 段 / 11497 点 |
| 湖泊 | `ne_10m_lakes` | 同上（ε=0.010°），保留闭合环 | 229 个面 |
| 水系 | `ne_10m_rivers_lake_centerlines` | 按 `scalerank` 分级，ε=0.010° | 435 段 / 17553 点 |

输出 `assets/basemap.js`，**588 KB**。全部为公有领域数据，不含任何国界、省界或政权疆域。

### 3. 投影与视野

- **Web 墨卡托**：`x ∝ 经度`，`y = ln(tan(45°+φ/2))`。栅格与矢量同投影，缩放时不会错位。
- **视野自适应**：以华北（105°E, 34°N）为中心，纬度基准 17°–53°（墨卡托跨度 45.4，约合纬度 13°–54°），经度跨度 = 纬度跨度 × 画布宽高比，再夹在栅格范围内。因此任何窗口比例下底图都铺满画布，不留空白边。
- 缩放范围 **1×–6×**。1× 即底图恰好铺满画布，再往下缩就会露出画布外的空白，故设为止点；复位按钮回到 1×，此时地图为最大可视范围。
- 平移有夹取：任何缩放级别下拖动，图片边缘都不会进入画布内侧，不会出现空白边（`clampPan()` 按栅格经纬／墨卡托范围实时校正 `tx/ty`）。
- **裁剪层与变换层分离**：`clip-path` 必须挂在**未做 translate/scale 的外层 `<g>`** 上，内层 `<g id="mapWorld">` 才承担平移缩放。若把 clip 直接加在带变换的图层上，裁剪框会随地图一起移动，拖拽后画布边缘就会露出一条无底图的空白（2026-11-03 修复）。
- 滚轮缩放需按住 Ctrl/⌘（避免与页面滚动冲突），另有 ＋/－/复位按钮。

## 四、页面结构

```
┌──────────────────────────────────────────────┐
│ 控制区：朝代 / 年份 / 事件类型 / 定位精度 / 重置  │
│ 图层：地形晕渲 水系 湖泊 海岸线 ｜ 点位 密度      │
├───────────────────────────────┬──────────────┤
│ 地图主体                       │ 右侧详情      │
│  · 地形栅格 + 矢量底图          │ · 地点名      │
│  · 事件点位 / 密度方格          │ · 今地对照    │
│  · 缩放按钮 / 图例 / 比例尺     │ · 定位精度    │
│  · 经纬注记                    │ · 关联事件数  │
│                               │ · 事件列表 →  │
└───────────────────────────────┴──────────────┘
```

- 控制区两行全部可见，没有折叠菜单。
- 地图占满剩余空间，右侧固定 372 px（窄屏 320 px，≤820 px 改为上下堆叠）。
- 点击点位 → 右侧立即显示该地点的今地、精度、事件数、事件列表；点事件 → 跳转事件名录并展开详情。

## 五、点位渲染

- **聚合**：屏幕距离 < 12 px 的点位合并为一个标记，事件数累加，地名并列（如「洛阳／怀州／怀、孟间」）。缩放后自动拆分。
- **尺寸**：按事件数 4.5 / 5.5 / 7 / 9 px 四档。
- **颜色**：取该点事件中占比最高的类型色。
- **形状**：州县级、区域级为实心圆；「大范围」为空心圆（示意中心）；「存疑」为虚线圆（当前无此类）。
- **注记**：按事件数从多到少放置，矩形碰撞避让，随缩放调整密度（低倍只标 ≥4 条事件者，放大后逐级放宽）。文字带纸色描边，压在底图上仍可读。
- **计数徽标**：≥3 条时显示数字；放大到 1.3× 以上时 ≥2 条也显示。

## 六、密度图

- 切换「密度分布」后隐藏点位，改画 1°×1° 方格，颜色由浅棕到深红（`#f6e7d6 → #8c3a34`），不透明度 0.30–0.82，按格内事件数取幂次 0.6 归一。
- 图例同步切换为色阶说明。
- 用于看宏观集聚（华北平原、关中、江淮），不替代点位图。

## 七、学术约束的落实

| 要求 | 落实方式 |
|---|---|
| 不为地点不详者生成坐标 | 14 条事件 `x=null`，不落点；详情注明「不落点」 |
| 不把「天下」定位为某城 | `precision=macro`，空心圆，侧栏提示「多地并列的示意中心」 |
| 不把历史区域等同现代政区 | 区域级取示意中心，侧栏标「区域级」 |
| 不把存疑地点表现为准确地点 | 当前无存疑地点；若有，以虚线圆标出 |
| 不用现代地名覆盖史料地点 | 注记只画 `n`（史料地名），今地仅出现在右侧面板 |
| 标明定位精度 | 点位形状 + 右侧面板 + 事件详情三处一致 |
| 不画国界与历史疆域 | 底图只有自然地理要素，无任何政治边界 |

## 八、为什么不用现成的历史地图项目

对 `jiangshan-map`（GPL-3.0，纯 SVG，1.9 MB VLQ 疆域快照 + 640 KB 控制器）的评估结论不变：**不复用其代码与数据**。

1. 许可证传染（GPL-3.0 会覆盖整个交付物）。
2. 体量与耦合远超需要。
3. 它的核心是疆域演变，本库需要的是点位聚合与联动。
4. 把事件点叠在示意性疆域上，会让人误以为二者有精确对应。

本版改为「栅格底图 + SVG 矢量 + JS 交互」的混合方案，仍然不引入 Leaflet / Mapbox，保持离线可开。这是用户建议的方向，也确实更贴合本库的需求。
